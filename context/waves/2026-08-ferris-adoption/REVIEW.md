# FERRIS Consumer Contract Role Review

Status: Accepted and complete
Scope: PARLOR-owned exact FERRIS `validation-plan` compatibility proof

## Product Value Governor

Pass. PARLOR is a named public consumer with prior measured FERRIS evidence.
The slice converts that unprotected research observation into a removable
consumer-owned compatibility test. It changes no game code, manifest,
dependency, lockfile, or validation command and consumes one pulse with no
successor.

## Rust Safety Steward

Pass. No PARLOR Rust source changes. The proof builds the exact pinned safe-Rust
FERRIS adapter in a temporary target and invokes only its read-only planning
command.

## Compiler Performance Engineer

Pass with no performance claim. The prior 9.4% result motivates the selected
shape but is not reasserted by this proof. CI cost is bounded by one exact
FERRIS build and two read-only planning invocations.

## Interop Boundary Auditor

Pass. Cargo retains workspace metadata and dependency authority. FERRIS
retains adapter and plan semantics. PARLOR pins only the consumer-visible
schema IDs, command version, package closure, activities, and fallback needed
for its own contract.

## AI Assurance Skeptic

Pass. The checker fetches or verifies the exact Git commit, requires a clean
source tree, builds with the pinned lockfile, rejects ambient Cargo alias
substitution, and checks both an accepted result and a structured fallback.
It does not accept prose or model assertion as proof.

## Ecosystem Strategist

Pass. The compatibility surface lives in the consumer repository and points to
the public FERRIS owner. No schema is copied, no adapter is forked, and no
parallel resolver or validation policy is introduced.

## Rust Maintainer

Pass. PARLOR product crates are untouched. The checker, contract, workflow,
wave, and README paragraph are isolated and can be deleted together without
changing ordinary Cargo behavior.

## Native Platform Adopter

Pass. The proof passed on the recorded Windows checkout and the pull request's
consumer workflow passed on GitHub's Ubuntu runner using the exact event
commit and exact public FERRIS pin.

## Scope Keeper

Pass. This is compatibility proof only. It does not execute selected work,
narrow owner validation, modify source, add a dependency, claim support, or
authorize automatic FERRIS upgrades.

## Validation Checker

Pass. Local exact-pin and fetched-pin modes passed, including the Cargo-alias
negative control. PARLOR release tests, Clippy, formatting, Python compilation,
and diff hygiene passed. The pull request's Ubuntu consumer workflow also
passed before merge.

## Autonomy Supervisor

Pass. The product outcome, one-pulse budget, completion condition, and
abandonment condition preceded implementation. Two independent review findings
were accepted and fixed inside the original slice: immutable event checkout
and Cargo-alias bypass. No corrective pulse or expanded authority followed.

## Control record

- product outcome: consumer-owned exact FERRIS compatibility proof;
- value obtained: PARLOR now detects drift in the accepted `parlor-go`
  reverse cone and repository fallback before adopting a later FERRIS pin;
- owner authority retained: PARLOR's three full validation commands remain
  mandatory and FERRIS remains read-only;
- budget consumed: one pulse, one implementation attempt, zero successors;
- migration: update the exact pin and intentionally adopted version IDs, then
  rerun local and consumer CI proof;
- rollback: restore the previous pin or delete the isolated proof surface;
- proposed next action: stop after merge; no automatic FERRIS expansion; and
- disposition: `continue-within-budget`.

## Decision

All eleven roles accept the bounded consumer contract. Merge only after the
consumer CI workflow passes. No role grants execution, validation narrowing,
support, stability, source modification, or successor authority.

The merge gate was satisfied by PARLOR PR
[#1](https://github.com/giodl73-repo/PARLOR/pull/1). The post-merge pin
migration from `5cd1aa9` to `8c0d674` and rollback to `5cd1aa9` both passed,
so the documented lifecycle is now measured rather than prospective.
